# Orin Dashboard 功能介绍与使用说明

MultiCamera / Orin · 文档版本 1.1（审阅与配图版） · 2026年11月14日

适用对象：设备使用人员、现场调试人员及系统集成人员。
适用范围：当前多相机 Dashboard 代码与 192.168.31.28 上的部署记录。软件版本为 0.9.0；本文不代表所有现场能力均已验收。

## 一、系统定位与访问方式

Orin Dashboard 是运行在 NVIDIA Jetson Orin 上的多相机浏览器控制台，用于集中查看三台设备的 RGB、红外、双目深度、点云及人体追踪结果，并进行相机配置、融合任务管理和状态检查。

浏览器访问：http://192.168.31.28:8092/
人体追踪入口：http://192.168.31.28:8092/#human

相机负责采集并提供图像接口；Orin 执行校正、模型推理、追踪和融合；浏览器展示结果并提交操作。正式服务已设置开机自启，不依赖 Host 电脑或 Codex。客户端需要能访问 Orin 所在网络。

状态说明：11月13日正式部署后，Dashboard 与追踪服务均为 active，网页 HTTP 200；三台相机连接超时，MQTT 发布关闭。11月14日编写本文时，SSH 连接超时，未能重新读取设备状态。以下功能说明基于代码和已保存记录，现场状态需连接恢复后确认。

截图来源与阅读方式：图1—图7为2026年11月14日使用当前前端源码本地渲染的操作示意，不是实时实机截图；图3回放2026年11月5日旧设备状态，图7为内置模拟场景。图8是2026年11月13日 .28 临时验收服务的历史实机截图。在线标记、人数、坐标和指标只对应各自来源，不能用于判断当前设备状态。

首次使用顺序：打开网页 → 设置与状态中检查供图与图像尺寸 → 原始画面 → 单机校正、深度与点云 → 按需选择融合或人体追踪。首次调试优先选择320×180与快速档，再逐步提高计算设置。

## 二、主要功能与使用前提

| 功能模块 | 主要能力 | 使用前提或边界 |
| --- | --- | --- |
| 原始画面 | 三台设备的 RGB 左目、RGB 右目、红外，共九路预览 | 相机在线；快照不代表硬件同步 |
| 双目深度与单机点云 | 校正对照、米制深度、彩色点云、分辨率与迭代配置 | 左右顺序及双目标定有效 |

| 多设备融合 | 共同码外参、深度采集、点云融合、可选 TSDF 网格 | 单机几何有效、共同码可见、相机和场景静止 |

## 三、画面预览、深度与点云

### 3.1 原始画面

进入“原始画面”后，每台设备显示 RGB 左目、RGB 右目和红外画面。可点击放大、暂停或继续预览，并手动刷新。画面按原始比例显示。

离线、请求失败、暂停及旧帧均需结合页面状态判断。显示了上一帧，并不代表设备仍在线；观察更新时间有助于区分静态场景和供图中断。

原始画面刷新间隔可选 750ms、1s、1.5s、3s。人体追踪页面的“流畅预览”采用独立预览路径，不能将两种模式的刷新设置混为一谈。

![图1 原始画面与模式入口 本地离线界面复现 设备列表来自历史配置](../output/docs/orin-dashboard-20261114/review-v1.1/screenshots/01-overview.png)

读图要点：顶部切换模式，右上角进入融合与设置。黑色占位区和重试提示表示无可用画面，不表示无人。

### 3.2 双目校正、深度与单机点云

点击“双目校正 · 深度 · 点云”，查看左右图校正结果、深度图和单机彩色点云。默认深度模型为 FoundationStereo，同一模型按需处理请求。

图像先按相机标定参数校正，再缩放到选定的模型输入尺寸。视差结合投影参数与双目基线转换为米制深度，再反投影为点云。显示范围为 0.2–10m：暖色近、冷色远，黑色表示无效深度。有效深度比例不等于模型置信度或测量准确率。

| 设置 | 可选值 | 含义 |
| --- | --- | --- |
| 深度分辨率 | 320×180、480×270、640×360、960×540 | 分辨率越高，计算与内存需求通常越高 |
| 模型档位 | 快速8次、标准16次、精细32次迭代 | 使用同一权重；增加迭代不保证每个场景都更准确 |
| 点云显示上限 | 1500、3000、6000点 | 调整浏览器显示量，不改变相机原始标定 |

深度计算包含采集、等待和推理，通常慢于原始预览。系统会合并重复请求，并按设备、分辨率和模型档位区分缓存；旧结果更新期间会显示相应状态。不能把页面刷新频率当作深度推理帧率。

每台设备的单机点云最初位于各自的校正左目坐标系。独立点云能够显示，不代表三台点云已统一到同一世界坐标系。

![图2 双目校正 深度与单机点云 本地界面复现 未生成模型结果](../output/docs/orin-dashboard-20261114/review-v1.1/screenshots/02-stereo.png)

读图要点：左到右为校正对照、深度和点云，上方选择模型输入与迭代档位。空结果只说明控件位置，不用于判断精度。

## 四、设置、状态与截图

### 4.1 设备与状态

打开“设置与状态 → 设备与状态”，查看通道在线情况、端口、当前图像尺寸、标定尺寸、预期 MAC、双目基线、标定会话与文件身份，以及 Orin 环境、模型和任务状态。

当前设备通过配置文件添加与维护，尚无局域网自动发现和网页新增设备流程。更换地址或相机后，需要更新设备配置；替换硬件不能沿用未经核验的标定有效性结论。

“哈希校验通过”只说明文件身份与预期匹配，不代表当前物理镜头绑定或测量精度已核实。在线通道仍可能与标定尺寸不匹配。

![图3 状态界面 当前前端回放2026年11月5日旧设备数据 非28当前状态](../output/docs/orin-dashboard-20261114/review-v1.1/screenshots/03-status.png)

读图要点：先看标定会话、基线与物理身份，再逐路比较尺寸。图中红外在线但尺寸不匹配，是历史记录示例。

### 4.2 相机参数

在“相机参数”选择设备与通道，先读取当前配置，再按需修改。RGB 控制包括曝光模式、曝光时间、增益、白平衡、色温、亮度、对比度、饱和度、锐度、防闪烁、动态帧率等；IR 可提供色板、温度标注和显示倍率。实际项目以相机返回的能力为准。

仅点击“应用相机参数”后才写入所选设备与通道。自动模式下，对应手动项不可编辑。写入后会读取确认，并使相关图像、深度缓存失效；出现失败提示时应重新读取，不能默认参数已生效。

预览分辨率、刷新间隔及点数等设置主要保存在当前浏览器；“追踪运行设置”写入 Orin 并可在服务重启后保留。两类设置的保存位置不同。

### 4.3 截图预览与 AprilTag 识别

在“预览设置 → 截图预览 · AprilTag 识别”中选择设备、左右目和截图分辨率，点击“拍照并识别码”，查看检测框并下载原图。

支持当前预览 1280×720 和相机原生拍照 1920×1080。原生拍照会短暂停止该设备的三路视频，结束后自动恢复，因此不宜在连续采集时频繁触发。

1080p 截图用于观察与码识别，不能直接代替已标定的720p图像求外参。当前融合外参流程仍使用与现有标定匹配的图像及参数。

读图要点：上方是深度计算设置，下方是截图采集设置。选择1080p截图不会自动改变外参和深度计算分辨率。

## 五、多设备点云融合

### 5.1 推荐流程

1. 在原始画面检查待参与设备在线，左右目顺序、尺寸与标定一致。
2. 在单机深度与点云页面核验基本几何。若单机点云已经弯曲或比例明显错误，应先处理单机问题。
3. 将同一个 AprilTag 放在各参与相机共同可见的位置。选择参与设备、码编号、黑色外边框实测边长与采样次数。
4. 点击“重新采集共同码并标定”，等待外参结果；已有匹配且有效的外参可直接使用。
5. 设置深度分辨率、迭代档位、融合帧数、最大深度及输出类型，点击“开始采集与融合”。
6. 查看一致性检查、任务耗时和结果，再按需下载产物或保存当前视图 PNG。

现场已确认的码黑色图案尺寸为 80×80mm，不能把含白边的整张纸尺寸填成码尺寸。界面使用 AprilTag 36h11，可指定编号或自动选择，外参采样次数为3–8次。

移动相机位置或改变俯仰角会改变外参。重新摆放相机、移动坐标基准或修改相关几何参数后，应重新核验并按需要重标定。

![图5 融合工作流与点云工具 本地界面复现 未提交任务 无真实融合点云](../output/docs/orin-dashboard-20261114/review-v1.1/screenshots/05-fusion.png)

关闭融合窗口只关闭界面，已提交到Orin的任务仍可继续；重新打开或刷新状态查看进度。服务重启和断电不属于同一情况，不能据此推断会自动续跑。

![图6 AprilTag外参设置局部 本地界面复现 80mm为历史确认值 现场需复核](../output/docs/orin-dashboard-20261114/review-v1.1/screenshots/06-fusion-parameters.png)

### 5.2 融合参数与缓存

| 项目 | 支持范围或选项 | 使用说明 |
| --- | --- | --- |
| 参与设备 | 从三台配置设备中选择 | 可仅选择共同码可见的两台 |
| 每台融合帧数 | 1–5帧 | 多帧可增加采集和处理时间 |
| 最大深度 | 0.5–10m | 可按关注区域限制远处噪声 |
| 输出内容 | 点云；点云与TSDF网格 | 仅看点云时可减少额外建模耗时 |
| 严格容差 | 尺度±5%、P90误差≤5cm | 法向一致性门限为10° |
| 预览容差 | 尺度±10%、P90误差≤15cm | 只用于观察，不能替代标定修正或精度验收 |
| 深度缓存 | 显式确认后复用 | 必须确认相机和场景未变化 |

融合窗口中的“下次分辨率/模型档位”作用于下一次融合任务，独立于当前结果与主页面预览。复用缓存可省去重复深度计算；相机移动、场景变化或几何配置改变后应重新采集。缓存有效期最长10分钟，服务重启、参数或外参变化后需重新采集；勾选复用不是自动判断场景未变化。

### 5.3 点云操作与坐标含义

支持自由旋转、平移、缩放、滚转，以及正视、俯视、侧视、立体、居中适配和复位；可调整点大小、RGB/高度着色、坐标轴、网格与设备图层。部分功能仅在结果提供相应数据时可用。

鼠标拖动旋转；Shift、右键或中键拖动平移；滚轮缩放；滚转模式横向拖动或 Q/E 调整画面倾斜；F或双击居中，Home复位。

共同码坐标系的 X/Y 沿码边缘、Z 垂直码面。“世界Z朝上”只调整观察视角，不修改导出点云，也不能证明已标定重力方向。点云融合外参与人体追踪地面标定是不同流程，不能自动互相替代。

## 六、人体识别、追踪与空间关联

### 6.1 模型与身份范围

人体检测与姿态使用 YOLO26n-pose，输出人体框与COCO17关键点。单机跟踪支持 ByteTrack、OC-SORT、TrackTrack，默认 ByteTrack。

人员 ID 用于匿名轨迹关联，不是人脸身份识别，也不能保证跨服务重启、长时间遮挡或离开后返回仍保持同一身份。暂停或修改主要追踪参数会重建轨迹并重新编号。

### 6.2 实时模式与演示模式

“实时追踪”展示相机输入、服务状态和真实轨迹；“演示场景”用于查看布局与交互，其中人员、轨迹、位置和指标属于模拟数据。验收和性能评估应以实时状态与保存报告为依据。

页面提供三路相机画面、人员列表与详情、关联动态，以及静态三维场景中的人员位置与轨迹。立体/俯视、轨迹、相机视野及人员联动等交互可用于查看空间关系，但真实坐标必须满足地面几何和时间条件。

### 6.3 单机追踪与跨机关联

单机图像内追踪不依赖共同地面标定；可在标定未就绪时保留每路本机ID。要跨相机统一空间坐标并关联人员，需要有效地面标定、固定相机、可用脚部关键点，以及经核验的采集时间与误差范围。

空间位置参考点为双脚踝中点投影到地面，单位为米；世界X/Y沿地面，Z=0。它表示人员地面位置，不是人体中心高度，也不是完整的三维骨架重建。

条件未满足时，界面会显示跨机关联 blocked 或位置待就绪，不应把空坐标当作原点。相机离线、无有效观察与场景中确实无人也需要区分。

当前网页没有完整的人体地面标定向导，需要通过部署端标定流程建立、写入并核验配置。融合窗口中的共同码外参不能自动完成这一项。

### 6.4 运行设置与帧率

可配置每路追踪采集上限0.5–25帧/秒、模型输入边长320/480/640/960、跟踪器、新目标置信度、人体框/骨架显示及逐帧核对JPEG画质。

“流畅预览 · 25FPS”是独立画面请求目标，不保证每秒25张不同的新帧，也不代表模型每秒推理25次。“逐帧核对”随追踪结果显示，便于核对叠加框与画面。模型输入尺寸不改变相机原始采集分辨率。

暂停追踪后模型仍可保留在内存中，不会立即释放全部GPU或整机内存；暂停不等于卸载模型。

性能评估应同时查看新画面更新率、实际处理帧率、帧龄、推理耗时及排队情况。回放评测属于离线视频结果，不等于三路现场吞吐。

## 七、MQTT与外部系统对接

系统具备 MQTT 发布模块，支持单机轨迹与条件就绪后的全局轨迹。进入人体追踪页的“MQTT 输出”，查看连接状态与实际topic。订阅凭据独立提供，不在网页显示。

11月13日的 .28 正式部署保留了原有 Broker，但新部署的追踪发布模块为 disabled。Broker进程运行不等于追踪消息已经发布；接入前需要配置并确认 connected。

下表以可配置的 topic_prefix 为前缀，通常为 multicamera/<node_id>，实际值以界面为准。

| Topic | 内容 |
| --- | --- |
| <topic_prefix>/availability | 在线状态与遗嘱 |
| <topic_prefix>/status | 服务、输入、关联和发布状态 |
| <topic_prefix>/cameras/<camera_id>/tracks | 单机人体框、关键点、本机ID和条件有效的空间坐标 |
| <topic_prefix>/global/tracks | 已关联全局轨迹及观察来源 |
| wyzl/iot/service/device/fusionmap/report | 可选旧JSON协议兼容输出，需独立启用 |

实时轨迹使用 QoS0且不保留；在线状态使用QoS1保留消息与遗嘱。消息携带会话、序列、时间、有效期及位置有效性等信息，接收方应检查新鲜度和坐标系；无有效位置时坐标为空，不补造温度、姿态或世界位置。

这些是PyTorch FP16结果，不含读取、上传、网络、深度换算和写盘；不代表原生1080p采集或多路实时帧率。Fast独立测试分辨率与网页默认模型的可选分辨率是两套配置。

## 九、日常操作与维护

### 9.1 开始使用

先打开Dashboard，确认处于所需模式，检查设备在线与更新时间。调试深度时先使用较低分辨率，确认左右校正与单机点云后再提高设置。做多设备融合或人体空间关联前，再核验对应的外参或地面标定。

现场验收至少区分四件事：网页服务可访问、相机实际供图、模型实际推理、几何与输出精度合格。前三项不能代替第四项。

### 9.2 常见现象处理

| 现象 | 优先检查 |
| --- | --- |
| 网页无法打开 | Orin电源、当前IP、同网段连通性和预览服务 |
| 页面可开但画面离线 | 相机电源/网线、当前IP、采集服务和图像端口 |
| 有画面但无深度 | 左右尺寸与顺序、标定文件、模型加载与任务错误 |
| 深度更新慢 | 分辨率、迭代次数、模型冷启动、GPU负载、排队和缓存 |
| 点云弯曲或融合错位 | 先看单机标定、尺度和左右对应，再看外参与码尺寸 |
| 画面能摆正但导出仍倾斜 | 显示视角不改变世界坐标，检查坐标基准与外参 |
| 有本机ID但没有全局ID | 地面标定、相机参与范围、脚踝位置与时间条件 |
| MQTT没有数据 | 发布是否启用、Broker连接/认证、实际topic与有效观察 |

### 9.3 .28维护入口

服务状态与日志命令需在Orin终端执行；重启会打断当前任务，应在维护时操作。

```sh
systemctl status multicamera-jp6-preview multicamera-jp6-tracking
journalctl -u multicamera-jp6-preview -n 100
journalctl -u multicamera-jp6-tracking -n 100
```

应用目录为 /home/nvidia/multicamera-jetson；current 指向启用版本，共享现场数据位于 shared/data。Fast独立目录为 /home/nvidia/multicamera-fast-stereo。

Fast TensorRT后台任务状态文件位于：

```text
/home/nvidia/multicamera-fast-stereo/trt/20261113/status.json
```

安装器支持JetPack5与JetPack6的已适配系统、全新隔离环境、按需模型资源、健康检查和版本切换；主安装包约253KB，不内置大权重。安装器不刷机，首次安装仍需获取依赖与模型。
