# calibcam 与现有 OPENCV5 联合优化：独立离线评估

日期：2026-11-01。

结论：当前 ChArUco 双目流程暂不引入 calibcam 运行依赖。三组固定留出没有显示它独有且有实际幅度的精度收益。旧数据约 0.38%（0.00195 px）的改善，用已有解析联合优化也能取得；其余两组基本一致。原生稀疏求解在两组普通初值下达到 500 次上限，不能将这些未收敛解略低的留出误差认定为优势。

## 研究对象和可迁移能力

核对的是 [BBO-lab 官方 calibcam](https://github.com/bbo-lab/calibcam)，版本 4.2.0，固定提交 `ca2a49d61252995708730f7d9aebca024a3dfceb`。本地源码位于 `data/research/calibcam_source`，保持未修改；未复制或改写其投影与自动微分实现。

- [流程和参数](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/calibrator_opts.py)：单目标定初始化后联合求解相机内外参和每帧板姿态，支持逐参数固定。针孔默认只开放 k1、k2，切向项和 k3 强制为零；直接比较默认值会混入模型差异。
- [原生求解入口](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/camfunctions.py)、[参数和坐标处理](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/optimization.py)：固定参考相机消除坐标自由度，SciPy TRF/LSMR 求解，默认线性损失。
- [原生残差与稀疏导数](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/repro/optfunctions.py)：JAX 自动微分，按相机与板姿态组织稀疏块，未观测位置以 NaN 表示并清零对应残差/导数行。统计误差时必须排除这些补位。
- [投影](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/camfunctions_ag.py)：固定 xi=0 时与中央针孔模型对应；五项畸变顺序为 k1、k2、p1、p2、k3。本实验显式开放全部五项，固定 skew 与 xi。
- [完整流水线](https://github.com/bbo-lab/calibcam/blob/ca2a49d61252995708730f7d9aebca024a3dfceb/calibcam/camcalibrator.py)另有检测、初始化、残差筛除等步骤。本轮调用原生联合求解核心，复用既有角点，不宣称复现其视频检测全流程。默认 50 px 筛点阈值远高于本轮各原生解约 2.54–3.34 px 的最大训练点误差，不会提供额外筛点收益。

值得保留的是多相机统一求解、混合镜头模型、参数约束与视频流程的工程组织方式。当前两相机、共同板角点、等权 OPENCV5 已有同类联合求解目标，自动微分本身没有增加新的测量信息。默认优化路径也没有为现有数据提供经验证的观测协方差或真实三维精度区间。

## 固定协议

独立入口：`scripts/compare_calibcam.py`。相机始终按会话文件左右关系使用，各数据集分别训练，不假定不同会话相机条件相同。

| 会话 | 历史角点与划分目录 | 实际训练/隔离/留出帧 | 训练/留出相机点观测 |
|---|---|---:|---:|
| 旧数据 `offline/calib_20260520_104534` | `data/results/mrcal_opencv5_final` | 24 / 2 / 9 | 5934 / 2166 |
| test1 `data/test1/calib_20261019_152613` | `data/results/mrcal_test1_retrained_verified` | 16 / 2 / 6 | 4024 / 1512 |
| 新数据 `data/mrcal_20261030/calib_20261030_135342` | `data/results/mrcal_20261030_detection` | 16 / 2 / 6 | 3854 / 1234 |

旧数据训练区间含一个历史无效帧 0015，保留原划分记录但不参与求解。test3 未纳入三组既有固定划分。

数据哈希依次为：

```text
463d0c5dc2099e0bdfa50c10ce46a6f84fb31864354f5eed5d75e3e26686b740
15733eda7d536dbd4004d9e338a9bc61b4abede15e2ef78e997e9f23532f7d0b
f5bdec1bee0ac8c4d6778f51ad05e5bf96f21a98dce18140fba0077da62abeee
```

所有方法使用原始缓存的相同共同 ID、像素观测、板规格和有效帧；不重新检测、加权或筛点。使用**应用实际 float32 板坐标提升为 float64**，保留原板原点和米单位；不使用早期研究脚本的理想双精度网格替换应用几何。每相机九个内参、右目六个外参、每训练帧六个板姿态，共 `24+6N` 个自由参数，左目为固定坐标系。

方法：

1. `application_joint`：直接调用当前应用单目和双目标定器，双目 `CALIB_USE_INTRINSIC_GUESS`，显式 1000 次上限、epsilon=1e-10，确实联合更新内外参。
2. `opencv_long_reference`：仅把双目上限改为 10000，其他相同，检查是否仍受迭代上限限制。
3. `analytic_double_control`：已有 `verify_calibration_information.py` 的双精度解析联合优化，等权，从应用解继续求解，作为无需新框架的数值参照。
4. `calibcam_sparse_from_fixed`：OpenCV 单目和固定内参双目初值，再调用未修改的原生联合优化核心。
5. `calibcam_sparse_from_application`：从应用联合解继续调用同一原生核心。
6. `calibcam_dense_control_from_fixed`：使用相同原生投影和 JAX 导数，单独把数值求解换成稠密 LM，区分目标函数与稀疏求解停止状态。此项是诊断对照，**不是 calibcam 默认配置**。

原生求解统一 CPU、float64、linear loss、`x_scale=jac`；max_nfev=500，ftol/xtol/gtol=1e-10。保留 native sparse 的 TRF/LSMR 设置，停止状态均如实报告。两种初值不根据留出表现选优。

主指标为留出二维点跨目预测 RMS：单独用一目拟合板姿态、预测另一目，合并双向点误差；不使用训练器各自的 RMS 直接比较。辅助指标为双目共同拟合板姿态后的点重投影 RMS、外侧 20% 图像区域的同口径误差，以及校正垂直差。留出只拟合每帧辅助板姿态，不更新相机参数。校正垂直差沿用历史每模型 stereoRectify(alpha=0) 口径，受输出缩放影响，不能作为共同视场或边缘拉伸指标。

## 留出结果

二维点跨目 RMS，单位 px，越低越好；`*` 表示原生求解达到 500 次上限，未成功收敛。

| 方法 | 旧数据 | test1 | 新数据 |
|---|---:|---:|---:|
| 应用联合优化 | 0.513190235 | 0.431530838 | 0.436273372 |
| OpenCV 10000 次参考 | 0.513190235 | 0.431530838 | 0.436273372 |
| 已有解析联合优化 | 0.511237616 | 0.431531486 | 0.436273270 |
| calibcam 原生稀疏，普通初值 | 0.511256786 | 0.431494625* | 0.436188949* |
| calibcam 原生稀疏，应用初值 | 0.511258793 | 0.431509549 | 0.436270063 |
| calibcam 原生投影/导数，稠密控制 | 0.511237624 | 0.431531598 | 0.436273221 |

三组应用 1000 与 10000 次参考的全部 K/D/R/T 完全一致，增加次数上限没有改变结果。旧数据更换双精度求解后还存在很小的目标下降空间，不能将“没有触及迭代上限”解释为不同求解器最终浮点解必须逐项相同。

旧数据原生稀疏从应用解出发改善约 0.376%，已有解析优化改善约 0.380%；test1 和新数据没有相当幅度的变化。原生稠密控制与已有解析优化的跨目 RMS 最大差约 `1.13e-7 px`，表明这里没有发现不同标定目标带来的额外收益。原生稀疏两个未收敛解略低的留出值不作为收益证据。

边缘共同拟合板姿态后的二维点 RMS，单位 px。边缘点数旧/test1/新分别 1156/256/816，三方法集合相同。

| 方法 | 旧数据 | test1 | 新数据 |
|---|---:|---:|---:|
| 应用联合优化 | 0.422451 | 0.300592 | 0.422684 |
| calibcam 原生稀疏，应用初值 | 0.421455 | 0.300555 | 0.422682 |
| calibcam 原生投影/导数，稠密控制 | 0.421443 | 0.300595 | 0.422684 |

没有稳定且有实际幅度的边缘改善。相应校正垂直差 RMS：应用为 0.366336 / 0.212538 / 0.353601 px；稀疏应用初值为 0.364036 / 0.212528 / 0.353549 px，量级结论相同。

## 收敛与数值核验

| 会话 | 原生稀疏普通初值：nfev / 状态 | 稀疏应用初值：nfev / 状态 | 原生稠密控制：nfev / 状态 |
|---|---|---|---|
| 旧数据 | 462 / ftol | 266 / ftol | 5 / ftol |
| test1 | 500 / 达到上限 | 125 / ftol | 5 / ftol |
| 新数据 | 500 / 达到上限 | 186 / ftol | 6 / ftol |

真实拟合的训练残差平方和（px²），同一原生目标：

| 会话 | 稀疏普通初值 | 稀疏应用初值 | 稠密控制 |
|---|---:|---:|---:|
| 旧数据 | 505.538824057 | 505.538829477 | 505.538753235 |
| test1 | 248.302202248 | 248.301954850 | 248.301895547 |
| 新数据 | 433.967658681 | 433.967479949 | 433.967406734 |

稀疏与稠密目标差很小，但稀疏梯度无穷范数约 0.36–2.98，稠密约 0.0024–0.0168；ftol 成功标记本身也不保证梯度足够小。相同目标下数值算法与停止条件足以产生这些小差异，不据此声称投影实现错误。本轮未继续调优 LSMR 或延长至 5000 次，故不推断其极限收敛速度。

原生稀疏实测纯求解约 3.4–10.6 秒，稠密控制约 0.37–1.04 秒；未包含导数审计和环境启动，应用计时还包含映射生成，不能直接作为完整应用性能对比。小型双目问题没有体现稀疏框架的规模优势。

独立检查：

- 每个原生初始状态与 OpenCV 同状态点投影核对，最大残差差 `<4e-10 px`。
- 24 个相机参数及 12 个分散板姿态参数的自动导数与独立中心差分核对，最大 `abs(diff)/(1+abs(numerical)) <1.68e-7`。
- 每个原生最终状态转换为既有坐标和参数顺序，重新计算训练残差平方和，与原生目标一致；缺失点补位不计入点数。
- 原始角点及缺失掩码逐项保持；参数有限、焦距正、基线正；合成无噪声控制能恢复已知几何。
- 实验记录的脚本、辅助求解、应用文件和原生文件哈希全部复核一致；原生源码 Git 状态干净。`report.json` 的 completed 只表示实验结束，原生求解是否成功必须看各 solver.success。

## 环境、复现与产物

使用隔离的 `data/.calibcam-eval-venv`：Python 3.10.20、OpenCV 4.13.0.92、NumPy 2.2.6、SciPy 1.15.3、bbo-calibcam 4.2.0、bbo-calibcamlib 0.5.3、JAX/JAXlib 0.4.38。选择 Python 3.10 兼容研究依赖；calibcam 本身声明 Python >=3.10。JAX 固定版本兼容该提交的 jit backend 调用；会产生上游弃用警告，实测均使用 CPU/float64。

安装与运行命令见本目录 README 的 calibcam 节。三个正式结果目录是 `data/results/calibcam_opencv5_old`、`calibcam_opencv5_test1`、`calibcam_opencv5_new`，各有 protocol.json、report.json、拟合状态 NPZ 和训练最大残差补充 audit.json。输出目录必须不存在，原结果不覆盖。固定划分与数据哈希均保存在协议中。

验证：应用环境加已有 mrcal 研究路径运行 `scripts/tests`，83 项通过、3 项原生依赖测试跳过；在独立 calibcam 环境运行 `scripts/tests/test_compare_calibcam.py`，5 项全部通过（其中含上述 3 项）。新文件 Ruff、编译检查通过。两次测试有 2 项重叠，不相加宣称额外测试数量。

## 当前建议和证据边界

保留独立脚本作为原生框架参照，当前不接入应用。若仅希望进一步打磨现有 OPENCV5，可把已有解析优化作为研究控制；本轮 0.002 px 级旧数据差异不足以支持新增应用功能或运行依赖。

若今后变成三台以上、混合镜头、部分相机不同帧可见标定板或需要复杂参数固定，再针对这些工程能力评估 calibcam，届时需要对应数据验证可观测性和初始化。当前共同角点双目结果不能外推为其多相机能力无价值。

历史留出已用于多轮研究，是固定验证集而非全新盲测；没有外部三维真值，也未输出物理精度或绝对不确定度结论。采图覆盖、图像模糊、板平整度或定位偏差仍不能由替换求解框架消除。本轮未改应用源码、UI、应用依赖或 Windows 打包，保留工作区已有应用改动。
